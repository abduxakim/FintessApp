# Модель данных

## Принципы
- `id` — UUID v7, генерируется на устройстве (сортируется по времени, без конфликтов).
- Синхронизируемые записи имеют `createdAt`, `updatedAt` (мс), `rev`, `deletedAt` (мягкое удаление).
- Конфликты: побеждает больший `updatedAt` (пользователь один).
- Каталог (упражнения, шаблоны, блоки, прогрессии) — в коде, версионируется с приложением. Пользовательские программы (этап 2) — отдельные записи с `owner: "user"`.
- Будущие аккаунты: облачные пути уже разделены по пользователю (`data/users/<id>`).

## Логическая модель (таблицы)
```
profile (1:1 user)      рост, вес*, пол, год, уровень, цель, фокусы, места, оборудование по местам,
                        дни/нед, длительность, слабая сторона, проблемные зоны, базовые результаты
goal_history            цель, дата смены
enrollment              программа, дата старта, следующий день, счётчик
exercise (каталог)      паттерн, мышцы (осн./вспом.), оборудование, места, сложность, тип учёта, техника, ошибки, статус проверки
progression (каталог)   ступени: упражнение + критерий перехода
program / day / item    подходы, повторы мин–макс или время, отдых, блок (разминка/основная/заминка)
workout_session         статус, программа/день, время начала/конца, заметки
session_exercise        упражнение, план, замена (swappedFrom), цель подходов, отдых, заметка
set_log                 тип, вес, повторы | повторы Л/П | время, выполнен, время отметки
```
`*` — чувствительные данные.

## Физическое хранение (агрегаты)
| Агрегат | IndexedDB | Облако |
|---|---|---|
| meta = profile + goal_history + enrollment | `meta["meta"]` | `data/users/<id>/fitness` |
| session = session + exercises + sets | `sessions[id]` | `…/fitness/sessions/<id>` |
| program (свои) | `programs[id]` | `…/fitness/programs/<id>` |
| очередь отправки | `outbox[key]` | — |

Тренировка хранится одним документом (~5–20 КБ) — так укладываемся в лимит облака (25 000 документов) на годы вперёд и пишем один документ на изменение.

## Запросы и производительность
Данные одного пользователя небольшие (сотни тренировок), поэтому все чтения идут из памяти:
«прошлый раз», рекорды и история считаются функциями `domain/history.ts` за один проход.
Если понадобятся графики за годы — добавим кэш дневных агрегатов (этап 2, `/database-optimizer`).

## Миграции
`schemaVersion` в meta и версии IndexedDB. Новые поля дополняются в `normalizeMeta`; структурные изменения — новой веткой в `onupgradeneeded` с бэкапом перед миграцией.
