# Подход: личный фитнес-трекер (артефакт Claude)

Память проекта для следующих сессий. Пиши пользователю **по-русски**. Пользователь один, тестирует на **Android** в приложении Claude.

## Как работать с пользователем
- Работать поэтапно, коротко объяснять, что сделано. На каждом этапе: **коммит → пуш → публикация артефакта**.
- Ветка: `ccr-9def6a9e-c7o3ee`. PR не создавать, пока не попросят.
- Артефакт (всегда обновлять ЭТОТ URL, публикуя тот же файл): https://claude.ai/artifact/XVTA3vWkCU1xGSHWKfip3X
  - файл: `apps/web/dist/fitness.html`
  - capabilities: `{"db": {}, "user": {}, "downloads": true, "sample": {"images": true}}` (при повторной публикации можно не передавать — сохраняются).
- Хостинг и платные сервисы не использовать: всё внутри артефакта Claude.
- Скиллы, которые пользователь просит использовать: /find-bugs, /code-reviewer, /vulnerability-scanner, /database-optimizer, /deep-research, /skill-creator. Скилл `.claude/skills/senior-qa` установлен по просьбе, но это пустой шаблон (скрипты ничего не делают). QA проводить самостоятельно через e2e-сценарии пользователя.
- Не делать медицинских утверждений, при боли рекомендовать врача. Если не уверен в данных об упражнениях, помечать `review: "check"`.
- Личные данные (вес, замеры) не коммитить в репозиторий. Наружу (в Claude через `sample`) отправлять только запрос, фото еды или тренажёра, цель, уровень, оборудование и названия проблемных зон, но не вес и не заметки.

## Контекст пользователя (для решений, без личных цифр)
- Зал. Тренируется 1–2 раза в неделю (иногда 3–4), по 90–120 минут.
- Цель: рельеф, удержание веса (рекомпозиция). Приоритет: спина и грудь, но остальное не забрасывать.
- Привычный сплит: спина+бицепс / грудь+трицепс / плечи+предплечья.
- Левое плечо щёлкает, мешает брать тяжёлый вес (боли нет). Левая рука сильнее: слабая сторона — правая.
- Привычка: круг 5-10-15 (подтягивания/отжимания/приседания, свои вариации, рекорд 7–8 кругов). Совет пользователю: в дни спины и груди ставить его в конец.
- Активная программа сейчас: «Рельеф: спина и грудь (моя)» — копия шаблона.
- 3D-анимацию и 2D-схемы движений **убрали по просьбе пользователя**: в «Как делать» только техника и ссылка на поиск YouTube.

## Стек и архитектура (`apps/web`)
- React 18 (UMD с jsDelivr + SRI, external) + TypeScript, Vite 8 (lib IIFE, oxc JSX classic). `scripts/build-artifact.mjs` собирает HTML-фрагмент со встроенными шрифтами (Golos Text, Unbounded, JetBrains Mono) и `dist/local.html` для тестов.
- Тёмная тема, токены в `src/styles.css`.
- Слои: `src/domain/*` — чистая логика с тестами; `src/data/*` — хранилище, синхронизация, каталог; `src/features/*` — экраны; `src/app/*` — навигация, действия, черновик.
- **Данные local-first**: память → IndexedDB → outbox → облако артефакта `db` по путям `data/users/<uid>/fitness` (meta), `…/sessions/<id>`, `…/programs/<id>`. При конфликте побеждает больший `updatedAt` (LWW). Бэкап — экспорт/импорт JSON (`downloads`).
- Meta: профиль, enrollment (программа идёт «по очереди», `nextDayIndex`, `carryOver`), `customExercises` (по фото), `programTweaks` (добавленные упражнения по дням и overrides подходов/повторов поверх шаблона).
- Навигация `app/nav.tsx`: стек слоёв, глубина пишется в хэш `#sN` (системная «Назад» на Android). `useScreenState` хранит состояние экрана и прокрутку, пока экран открыт. Для закрытия и последующего открытия использовать `backThen`.
- AI через `sample`: тренировка по запросу (`domain/planner.ts`, запасной разбор по ключевым словам на уровне мышц) и фото тренажёра (`domain/photo.ts`, сжатие с очисткой EXIF). Ответы всегда валидировать.
- Каталог: ~110 упражнений (`data/seed/exercises.ts`, с описанием нагрузки `LOAD`), 8 шаблонов программ с чередованием `a|b|c` и блоки (`data/seed/programs.ts`).

## Проверка перед каждой публикацией
```bash
cd apps/web
npx tsc --noEmit && npx vitest run   # unit-тесты, сейчас 53
npm run build                        # dist/fitness.html
npm run e2e                          # сквозной сценарий в Chromium, сейчас 50 проверок
SHOTS_DIR=<scratchpad>/shots npm run e2e   # со скриншотами для просмотра
```
- e2e подменяет `window.claude` фейками (`db`, `user`, `sample`). Сценарии пишутся по жалобам пользователя (назад, прокрутка, обрезанные кнопки — проверка `overflow` на каждом снимке).
- npm ставить с `--legacy-peer-deps` (есть `.npmrc`). Playwright подключать через `createRequire`.

## Подводные камни
- Селекторы `useStore` кэшируются по (state, selector), иначе возвращаемые массивы зацикливают рендер.
- В нижнем листе `.sheet > * { flex-shrink: 0 }`: иначе список с `overflow:hidden` сжимается и не прокручивается.
- Кнопки в 2 колонки и `.btn.block` переносят текст: длинные подписи раньше обрезались на телефоне.
- `\b` в регулярках не работает с кириллицей.
- Поле с `capture` всегда открывает камеру, поэтому у галереи отдельное поле без `capture`.
- cdnjs и api.github.com из контейнера отвечают 403; raw.githubusercontent.com и npm доступны.
